# Project overview

The short version, written so you can explain the project to anyone.

## The pitch (30 seconds)

**Pixel Hopper** is a small portrait-mode pixel platformer with 10 stages. You run and jump, stomp enemies, dodge spikes
and pits, collect coins and reach the flag. It plays in a web browser on desktop and phones and is published free on
itch.io: <https://the-protagonist07.itch.io/pixel-hopper>.

What makes the project unusual: **there are no art, music or sound files in it.** Every sprite is painted by code,
every sound and the music loop are synthesised by code, every stage is generated by code, and the logo and store
images are rendered by code. The whole game is about 5,000 lines of C# (including comments) and the finished web build is
about 11 MB (mostly the Unity engine itself; the game's own data is tiny).

## Why it exists

- A fast, low-risk experiment to learn how publishing a browser game on itch.io works and how players react.
- A complete small game as a showcase: design, code, art, audio, build and release.
- A base to grow: modes, scores, more enemies and characters, then possibly mobile stores (see [ROADMAP.md](ROADMAP.md)).

## By the numbers

| Item | Value |
|---|---|
| Engine | Unity 6 (6000.6.4f1), Universal Render Pipeline, 2D |
| Language | C# (14 runtime scripts + 1 editor tool) |
| Platform | WebGL (browser); built on macOS |
| View | Portrait 9:16, 15 tiles tall, about 8.4 tiles wide |
| Stages | 10, each a different world (sky, scenery, particles, palette) |
| Stage length | 6 chunks in stage 1 growing to 15 chunks in stage 10 (about 220 tiles) |
| Enemy types | 1 (purple blob), speed rises per stage |
| Hazards | Spikes and pits |
| Lives | 3 per run (max 5), +1 per cleared stage, bonus hearts in stages; game over restarts at stage 1 |
| Controls | Keyboard, gamepad and touch |
| Audio | 9 synthesised sound effects + a 6-second looping tune |
| Imported assets | None (no textures, audio, fonts, models) |
| Cost to play | Free |

## Tech stack

| Part | Choice | Why (details in [DECISIONS.md](DECISIONS.md)) |
|---|---|---|
| Engine | Unity 6 with URP | Mature 2D physics, WebGL export, good editor tooling |
| Input | New Input System | One API for keyboard, gamepad, mouse and touch |
| Rendering | SpriteRenderers + one sprite atlas | Few draw calls, crisp point filtering |
| UI | uGUI RawImage canvas driven in immediate mode | Correct colors in linear color space; no UI prefabs |
| Art | `PixelPainter` shading + per-pixel generators | Consistent 3D-looking pixel art with no image files |
| Audio | Phase-accumulator synthesiser | Tiny download, consistent chiptune style |
| Levels | Deterministic chunk generator | Endless variety, always completable, no level files |
| Web | Custom HTML template, gzip build | Branded loader, small download, works on phones |
| Distribution | itch.io HTML5 hosting | Zero cost, instant publishing |
| Source control | Git + GitHub (`TheProtagonist07/pixel-hopper`) | Backup, history, portfolio |

## What the player sees (flow)

1. **Loading screen** (HTML page): title and progress bar.
2. **Title screen**: bobbing 3D logo, hero and enemy mascots, "press space / tap to start".
3. **Help dialog** (first time only): controls and goals, with OK and SKIP buttons.
4. **Stages 1 to 10**: banner with the stage name, play, flag, short celebration, next stage.
5. **Game over** (out of lives): tap to start over at stage 1.
6. **You win** (after stage 10): coin total, tap to play again.

## How the project is organised

```
Assets/
  Scripts/             all gameplay and UI code (14 files)
  Editor/CoverArt.cs   editor-only branding/page-art generator
  WebGLTemplates/      custom web page for the build
  Scenes/SampleScene   contains only the camera and one Game object
docs/                  this documentation
CHANGELOG.md           what changed in each version
README.md              short project intro
```

The scene is almost empty on purpose: a camera and a single `Game` object. Everything else (stage, player, enemies,
coins, backgrounds, UI) is created at runtime. See [ARCHITECTURE.md](ARCHITECTURE.md).

## How it was made

Built in Unity by the owner, who made the product decisions (portrait, 10 stages, visual direction, publishing), tested it on a real iPhone, and published it on itch.io.

## Honest limitations

- One enemy type and one hero; stages are variations on a theme (see [ROADMAP.md](ROADMAP.md) for plans).
- No score or timer yet, so there is little replay incentive.
- Stage 10 is hard and stage 1 is easy ([KNOWN_ISSUES.md](KNOWN_ISSUES.md)).
- Audio and graphics are deliberately simple; they are procedural, not hand-crafted.
