# Project layout

Everything about Pixel Hopper lives in **one folder and one Git repository**: the Unity project folder (`~/pixel-hopper`, GitHub `TheProtagonist07/pixel-hopper`, private).
Code, documentation, marketing, management, sales notes and builds are all here, so a commit, a pull request or a clone always sees the whole project.

## Folder map

```
pixel-hopper/
  Assets/            game code, scenes, editor tools, WebGL page template   (Unity imports this)
  Packages/          Unity package list                                      (Unity)
  ProjectSettings/   Unity settings, including the version number           (Unity)
  docs/              engineering documentation: architecture, scripts, art, audio, testing, decisions
  marketing/         everything that promotes the game
    branding/          logo, itch cover, icon                 (made by Tools > Pixel Hopper > Generate Branding)
    page/              itch.io page background, banner, launch cover
    promo/             promo clip (mp4 and gif)
    screenshots/       v1.0.0-polish/ and one folder per update (vX.Y.Z/)
  management/        how the project is run: README, release log, status
  sales/             traction and monetisation: README, metrics log, store plan
  builds/            WebGL builds and itch.io zips per version          (NOT in Git)
  tools/             helper scripts
  README.md  CHANGELOG.md
```

Folders Unity creates itself (`Library/`, `Logs/`, `Temp/`, `UserSettings/`, `obj/`, `*.csproj`, `*.slnx`) are ignored by Git and can be deleted and regenerated at any time.

## Why extra folders next to Assets are safe
Unity only imports `Assets/`, `Packages/` and `ProjectSettings/`. Folders such as `marketing/` or `builds/` at the project root are never imported, so they cannot slow Unity down
or end up in a build.

## What is in Git (GitHub, private) and what is not

| Folder | In Git? | Size | Notes |
|---|---|---|---|
| `Assets/`, `Packages/`, `ProjectSettings/`, `docs/`, `tools/`, root files | Yes | small | the game and its documentation |
| `marketing/` | Yes | about 5 MB | images and the promo clip are small, so they are backed up with the code |
| `management/`, `sales/` | Yes | tiny | plain text |
| `builds/` | **No** | about 89 MB | large and regenerable; ignored by `.gitignore` |
| `Library/`, `Logs/`, `UserSettings/`, `Temp/` | No | large | generated by Unity |

**Backups and redundancy**
- The repository (code, docs, marketing, management, sales) is on GitHub, which is the off-machine copy.
- Each shipped build zip is attached to a GitHub Release for its version tag, so every release can be downloaded again without putting 11 MB zips into the Git history.
  Command: see "Backing up a build" in [WEBGL_BUILD_AND_ITCH.md](WEBGL_BUILD_AND_ITCH.md).
- The local `builds/` folder keeps all versions on this machine. Old unzipped build folders (`builds/vX.Y.Z/`) can be deleted to save space: they can be recreated from the zip.

## Rules of thumb
1. New files go in the folder that matches their job (see the map). Do not create a second project folder elsewhere.
2. Anything generated by a tool has a fixed destination: branding and page art go to `marketing/`, screenshots to `marketing/screenshots/vX.Y.Z/`, builds to `builds/`.
3. Moving or renaming the project folder needs the project to be re-added in Unity Hub. Nothing in the code uses an absolute path.
4. After a change, update `CHANGELOG.md` and the relevant docs ([DEV_NOTES.md](DEV_NOTES.md), "Releasing an update").
